COA mini project · Parallelism: Need and Applications

How much faster can a computer get by working in parallel?

Parallel Lab runs one heavy calculation on one worker, then splits it across many, and measures the difference live on this device. No simulation, no stored numbers.

See how it works

Runs in your browser. Nothing you measure is uploaded.

The need

Chips stopped getting much faster. They started getting more cores.

Until the mid-2000s, each new processor simply ran at a higher clock speed. Then heat became the limit, so manufacturers put several cores on one chip instead. A program only benefits from those extra cores if its work is written to be split between them.

Where it is used, and what gets split

Weather and climate

The atmosphere is divided into regions, and each core simulates its own regions.

AI model training

Training is mostly matrix multiplication, the same operation tested on this page.

Image and video

Frames and blocks of pixels can often be processed at the same time.

Engineering simulation

Crash and airflow models break a shape into small elements solved in groups.

The method

One job, one answer, two ways of doing it.

The job is multiplying two large square matrices. It is heavy on the CPU, and each row of the answer can be worked out without waiting for any other row, so it splits cleanly.

  1. Sequential version

    One worker thread computes every row of the answer, one after another.

  2. Parallel version

    The rows are divided equally between several workers, each on its own thread, running exactly the same code.

  3. A fair comparison

    Every worker warms up first, then we take the median of repeated runs. Timing includes sending out the work and assembling the result, and both answers are checked against each other.

Speedup

S = T1 ÷ Tp

How many times faster the job finished using p workers.

Efficiency

E = S ÷ p

How well each worker was used. 100% means nothing was wasted.

Worked example

800 ms ÷ 250 ms = 3.2×

If 4 workers take 250 ms where 1 worker took 800 ms, then 3.2 ÷ 4 gives 80% efficiency.

The limitations

Why doubling the workers doesn't double the speed.

Parallelism has a ceiling. Part of every program has to run one step at a time, splitting work costs time of its own, and all the cores share the same memory.

The serial part

Dividing up the job and assembling the answer happen in one place, however many workers there are. Amdahl's law says this part sets a hard ceiling on speedup.

Coordination overhead

Workers have to be given their rows and send results back, which takes time the sequential version never spends.

Shared hardware

Cores compete for the same memory and cache. Logical processors may also share a physical core, so gains often flatten early.

Small jobs: when splitting isn't worth it

On a small job, overhead can outweigh the gain. This test shrinks the job to find out where. Bars below the 1× line were slower than one worker.

The conclusion

So, how can parallel processing help?

It can cut the running time of heavy calculations dramatically, as long as the job is large enough and most of it can be split. Run the experiment and this section fills in with your own measurements.

      How to read these numbers responsibly

      This is a browser measurement for learning, not a hardware benchmark. Results change with your CPU, browser, background activity and temperature, so repeat a run before comparing settings. Efficiency above 100% can come from timing noise or cache effects. The Amdahl fit lumps together everything that limits scaling, including memory contention and overhead, so read it as an estimate rather than a measured serial fraction. Setting up workers and copying the matrices happens before timing starts.
